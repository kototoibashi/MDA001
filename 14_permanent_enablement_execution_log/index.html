    📝 14. 無線機能恒久有効化（アプローチ A）実施完了記録・変更ログ¶

    本ドキュメントでは、本端末（********）に対して 2026年8月6日に実施した無線機能（Wi-Fi / Bluetooth / セルラー）の恒久有効化（永続化）の実際の変更内容、変更ファイル、および実施後の確認結果 を記録・保存しています。

    📌 1. 実施概要 (Execution Overview)¶

    • 実施日時: 2026年8月6日
    • 対象端末: Qualcomm MSM8953 (Snapdragon 625) / MeiG SLM758 / Android 10
    • 適用方式: アプローチ A（/vendor パーティション直接修正 ＋ 自動ロード init サービスの追加）
    • 安全担保: 実施前に /backup_images/vendor.img のフルバックアップを取得・確認済み

    📂 2. 実際に変更したファイルとコード差分 (Diff)¶

    ① /vendor/bin/init.class_main.sh (起動時プロパティ自動注入スクリプト)¶

    • 変更箇所: Line 40
    • 変更内容: 起動時に強制的に noril (No RIL) を注入していた処理を無効化。 
       case "$baseband" in
     "apq" | "sda" | "qcs" )
-    setprop ro.vendor.radio.noril yes
+    setprop ro.vendor.radio.noril no
     stop ril-daemon
     stop vendor.ril-daemon
     stop vendor.qcrild
 esac

    ② /vendor/build.prop (ベンダービルドプロパティ)¶

    • 変更箇所: Line 109-110
    • 変更内容: MeiG Mobility 独自および AOSP の Radio 封印プロパティを解除。 
      -ro.meig.feature.wifionly=true
-ro.radio.noril=true
+ro.meig.feature.wifionly=false
+ro.radio.noril=false

    ③ /vendor/etc/init/init.radio_enable.rc [新規作成ファイル]¶

    • 作成ファイル: /vendor/etc/init/init.radio_enable.rc (権限: 644, 所有者: root:root)
    • 目的: 端末起動時 (boot時) に Qualcomm WCNSS Pronto Wi-Fi ドライバ (pronto_wlan.ko) を自動で insmod ロードさせる。 
      service load_wifi_driver /vendor/bin/sh -c "insmod /vendor/lib/modules/pronto_wlan.ko"
    class early_hal
    user root
    group root
    oneshot
    seclabel u:r:init:s0

    ④ Android 設定データベース (Settings DB)¶

    • 変更内容: 機内モードを常時 OFF に設定固定化。 
      adb shell settings put global airplane_mode_on 0

    📊 3. 変更適用後の動作検証結果 (Verification Results)¶

    再起動（adb reboot）後に端末の各種プロパティ・ネットワーク・UI の動作を測定し、正常適用を確認しました。

    1. プロパティ検証 (getprop)¶

    $ getprop ro.radio.noril
false

$ getprop ro.vendor.radio.noril
no

$ getprop ro.meig.feature.wifionly
false
    ➔ 起動時の無効化マスクが完全解除されていることを実測確認。

    2. Wi-Fi インターフェース自動生成検証 (ip addr)¶

    再起動直後にコマンドを発行： 

    $ ip addr show wlan0
27: wlan0: <BROADCAST,MULTICAST> mtu 1500 qdisc noqueue state DOWN group default qlen 1000
    link/ether XX:XX:XX:XX:XX:XX brd XX:XX:XX:XX:XX:XX
    ➔ 手動コマンドなしで電源オン直後に wlan0 インターフェースが自動現出することを確認。

    3. アクセスポイント実測検出検証¶

    $ iw dev wlan0 scan | grep SSID
    SSID: [MASKED_SSID]
    SSID: ctc-x2937f
    ➔ 周辺 2.4GHz 帯の Wi-Fi 電波をリアルタイムで正常取得。

    4. Android 純正「設定」アプリ UI 検証¶

    • 結果: 完全な成功には至らず（設定アプリのトップメニューにWi-FiやBluetoothの項目は表示されないまま）。
    • 現状の運用: ただし、Activityを直接叩く系のアプリ（Activity Launcher等）から android.settings.WIFI_SETTINGS などを直接起動することは可能であり、「Wi-Fi の使用」トグルスイッチおよびネットワーク一覧画面自体は正常に動作する。実運用上これで困っていないため、メニューに表示させるためのさらなる深追いはしていない状態。

    🔙 万が一の復旧・リストア方法¶

    万が一将来元の状態（完全無効化状態）に戻したい、あるいは問題が発生した場合は、以下のいずれかの方法で100%復元可能です。

    1. イメージ書き戻し法:
    2. 保管済みの backup_images/vendor.img を QFIL / EDL / Fastboot または dd で /vendor パーティションへ上書きレスキューする。
    3. 手動リバース法:
    4. /vendor/bin/init.class_main.sh の no を yes に戻す。
    5. /vendor/build.prop の ro.radio.noril を true に戻す。
    6. /vendor/etc/init/init.radio_enable.rc を削除する。
