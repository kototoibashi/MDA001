    📻 11. Radio（Wi-Fi / BT / セルラー）無効化原因・有効化可能性調査報告書¶

    本ドキュメントでは、本端末（********）における Radio 系機能（Wi-Fi, Bluetooth, セルラー/RIL通信）が全無効化されている原因の調査結果、下位サブシステム・プロセスの稼働状態、および有効化の可能性とロードマップをまとめています。

    📌 1. 調査概要 (Executive Summary)¶

    • 調査目的: 無効化されている Radio（無線通信）機能の有効化可能性の評価と原因特定
    • 調査方式: ADB Shell 経由による完全リードオンリー調査（システム設定の書き換え、コマンドによる変更操作は一切未実行）
    • 調査日時: 2026年8月6日

    📊 有効化可能性の判定結果¶

    機能 有効化の可能性 主な障害要因 有効化に必要なアクション
    Wi-Fi 極めて高い (ほぼ確実) ・機内モード (airplane_mode_on=1)
    ・ソフト機能OFF (wifi_on=0)    		 機内モード解除 / svc wifi enable
    Bluetooth 極めて高い (ほぼ確実) ・機内モード (airplane_mode_on=1) 機内モード解除 / svc bluetooth enable
    セルラー (3G/4G/SIM) 高 (条件付き) ・機内モード (airplane_mode_on=1)
    ・ro.radio.noril=true による Framework マスク
    ・init スクリプトによるプロパティ動的注入    		 ① 機内モード解除
    ② ro.radio.noril=false 化 ＆ init.class_main.sh 修正
    ③ 物理SIMスロット・アンテナ配線の確認

    🔍 2. 無効化の 2 大要因 (Root Causes)¶

    調査の結果、ハードウェア（基板・モジュール）の未搭載や物理的破壊ではなく、ソフトウェア設定上の二重遮断によって無線機能が全停止していることが判明しました。

    ① 機内モード (Airplane Mode) による無条件全遮断¶

    • settings get global airplane_mode_on ➔ 1 (有効)
    • settings get global airplane_mode_radios ➔ cell,bluetooth,wifi,nfc,wimax

    端末全体で機内モードが ON に設定されており、cell, bluetooth, wifi の全モジュールへの給電および通信要求がソフトウェアレベルで遮断されています。dumpsys wifi でも mAirplaneModeOn true かつ WifiDisabledState と記録されています。

    ② ro.radio.noril=true による Android Framework の抑制¶

    Android Framework（SystemServer, TelephonyManager, Settings UI）が本端末を「Wi-Fi Only (通話・セルラー機能なし) 機器」として認識するようにプロパティが設定されています。

    📂 3. 関連プロパティ・起動スクリプトの解析¶

    調査により、ro.radio.noril プロパティは単なる static なファイル定義にとどまらず、OS起動時に init スクリプトによって動的注入されていることが判明しました。

    プロパティ設定・スクリプトの位置一覧¶

    1. /vendor/bin/init.class_main.sh (Line 40) 
      setprop ro.vendor.radio.noril yes
    2. 起動時にシェルスクリプトが強制的に ro.vendor.radio.noril を yes にセットします。
    3. /vendor/etc/init/hw/init.qcom.rc (Line 1042-1043) 
      on property:ro.vendor.radio.noril=*
    setprop ro.radio.noril ${ro.vendor.radio.noril}
    4. ro.vendor.radio.noril の変化を検知して、自動的に ro.radio.noril プロパティを同期させます。
    5. /vendor/build.prop (Line 110) 
      ro.radio.noril=true
    6. /system/build.prop (Line 257) 
      PRODUCT_PROPERTY_OVERRIDES += ro.radio.noril=true

    🧩 4. 下位サブシステム・プロセスの稼働エビデンス¶

    上位 Framework や UI で Radio が無効化されている一方で、Qualcomm MSM8953 + MeiG SLM758 の下位通信スタック・デーモン群はバックグラウンドで正常に起動・稼働しています。

    デバイスノード・プロパティ確認結果¶

    • /dev/rmnet_ctrl (データ通信制御ノード): 存在確認

    • /dev/smd2, /dev/smd3, /dev/smd7 (Bluetooth制御ノード): bluetooth:bluetooth 権限でオープン状態

    🛠️ 5. 将来の有効化に向けた推奨ロードマップ (Enablement Roadmap)¶

    Phase 1: Wi-Fi / Bluetooth の簡易有効化 (Root不要)¶

    1. 機内モードの解除:
    2. ADB コマンド: settings put global airplane_mode_on 0
    3. ブロードキャストの送信: am broadcast -a android.intent.action.AIRPLANE_MODE --ez state false
    4. Wi-Fi / BT サービスの個別有効化:
    5. svc wifi enable
    6. svc bluetooth enable

    Phase 2: セルラー (SIM / モバイルデータ通信) の有効化 (要Root / システム書き換え)¶

    1. 起動スクリプトの修正:
    2. /vendor/bin/init.class_main.sh 内の setprop ro.vendor.radio.noril yes をコメントアウトまたは no に変更。
    3. ビルドプロパティの修正:
    4. /vendor/build.prop および /system/build.prop の ro.radio.noril=true を false に書き換え。
    5. ハードウェアの物理確認:
    6. メイン基板上の SIM カードスロットの実装有無（ソケットがハンダ付けされているか）。
    7. LTE / 3G アンテナ用同軸ケーブル（IPEXコネクタ）が配線・接続されているかの物理確認。
