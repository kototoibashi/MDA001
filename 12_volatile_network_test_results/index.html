    🧪 12. Volatile（非永続）ネットワーク有効化テスト結果報告書¶

    本ドキュメントでは、本端末（********）において封印されていた Radio 機能（Wi-Fi, Bluetooth, セルラー）に対し、メモリ上および一時設定データベース（Volatile環境）で実施した実働テストの結果およびキャプチャエビデンスをまとめています。

    📌 1. テスト概要 (Test Overview)¶

    • テスト目的: ソフトウェア封印されている無線モジュールの実動作可否を、物理・MAC・アクセスポイントスキャンレベルで実証すること。
    • テスト方式: 永続ファイル（/system, /vendor 等）を一切改変しない Volatile（非永続）実行
    • 前提条件: SIMカード未挿入
    • テスト日時: 2026年8月6日

    📊 検証結果サマリー¶

    機能 検証項目 テスト結果 実証された状態
    Wi-Fi ドライバ起動・MAC取得・SSIDスキャン 100% 成功 🎉 ドライバロード成功、wlan0 生成、周辺AP ([MASKED_SSID] 等) の実測スキャン成功
    Bluetooth アダプター有効化リクエスト 成功 APPLICATION_REQUEST イベントが正常ログ記録
    セルラー (RIL) モデム応答・プロパティ上書き 一部制約あり モデム ONLINE 継続。ro. プロパティのため setprop 単体は拒否（要スクリプト修正）

    🔍 2. 詳細検証手順と実測エビデンス (Detailed Evidence)¶

    Phase 1: 機内モードの解除 (Airplane Mode OFF)¶

    機内モードによる全ラジオ遮断をソフト的に解除しました。

    • 実行コマンド: 
      adb shell settings put global airplane_mode_on 0
adb shell am broadcast -a android.intent.action.AIRPLANE_MODE --ez state false
    • 実行結果: 
      Broadcasting: Intent { act=android.intent.action.AIRPLANE_MODE flg=0x400000 (has extras) }
Broadcast completed: result=0
0
      airplane_mode_on が 0 (OFF) に遷移しました。

    Phase 2: Wi-Fi (Qualcomm WCNSS Pronto) ドライバのロードとインターフェース創出¶

    カーネルモジュール pronto_wlan.ko を手動インサート（insmod）し、通信インターフェースを創出させました。

    • 実行コマンド: 
      adb shell insmod /vendor/lib/modules/pronto_wlan.ko
    • 検出されたネットワークインターフェース (ip addr): 
      32: wlan0: <BROADCAST,MULTICAST> mtu 1500 qdisc noqueue state DOWN group default qlen 1000
    link/ether XX:XX:XX:XX:XX:XX brd XX:XX:XX:XX:XX:XX
33: p2p0: <BROADCAST,MULTICAST> mtu 1500 qdisc noqueue state DOWN group default qlen 1000
    link/ether XX:XX:XX:XX:XX:XX brd XX:XX:XX:XX:XX:XX
      wlan0 (Wi-Fi) および p2p0 (Wi-Fi Direct) の物理MACアドレス（XX:XX:XX:XX:XX:XX）が正しく認識・生成されました。

    Phase 3: インターフェース wlan0 の UP 起動 ＆ 周波数スキャン実測¶

    wlan0 を有効化 (UP) し、周囲の電波（アクセスポイント）を実測スキャンしました。

    • 実行コマンド: 
      adb shell ip link set wlan0 up
adb shell iw dev wlan0 scan | grep -iE 'SSID|BSS|freq'
    • スキャン実測データ (抜粋): 
      BSS XX:XX:XX:XX:XX:XX(on wlan0)
    freq: 2462
    SSID: [MASKED_SSID]
        * OBSS non-GF present: 0
    Extended capabilities: HT Information Exchange Supported, BSS Transition
BSS XX:XX:XX:XX:XX:XX(on wlan0)
    freq: 2462
    SSID: [MASKED_SSID]
      周辺に存在する 2.4GHz 帯の Wi-Fi ルーター（[MASKED_SSID] 等）および SSID、BSSID、周波数がリアルタイムで完璧に実測検出されました。

    Phase 4: Bluetooth アダプター有効化テスト¶

    Bluetooth アダプターへの有効化シグナルを発行しました。

    • 実行コマンド: 
      adb shell settings put global bluetooth_on 1
adb shell svc bluetooth enable
    • ログキャプチャ (dumpsys bluetooth_manager): 
      Enable log:
  12-12 20:22:19  Enabled  due to SYSTEM_BOOT by android
  12-12 22:13:48  Enabled  due to AIRPLANE_MODE by android
  12-12 22:14:04  Enabled  due to APPLICATION_REQUEST by null
  12-12 22:16:59  Enabled  due to APPLICATION_REQUEST by null
      Bluetooth アダプターへのオン要求（APPLICATION_REQUEST）が正常に渡されたことが記録されました。

    Phase 5: セルラー (RIL) の動的変更制限の確認¶

    • 実行コマンド: 
      adb shell setprop ro.vendor.radio.noril no
    • 結果: setprop: failed to set property 'ro.radio.noril' to 'false'
    • 考察: Android のセキュリティ仕様上、ro. (Read-Only) プロパティは起動後の setprop 単体による動的上書きがブロックされます。したがって、セルラー機能を完全復元するためには、起動スクリプト /vendor/bin/init.class_main.sh の書き換え（Root化）が必須であることが実効テストにより確定しました。

    🛠️ 3. 恒久有効化（Permanent Enablement）を行う場合の必要作業¶

    将来的に、端末起動時に自動で Wi-Fi / Bluetooth を有効化したい場合の必要作業一覧です。

    1. Wi-Fi ドライバの起動時自動ロード化:
    2. init スクリプト等に insmod /vendor/lib/modules/pronto_wlan.ko を追加。
    3. 機内モードの初期値変更:
    4. 設定 DB (settings_global.xml) で airplane_mode_on を 0 に設定。
    5. ro.radio.noril 抑止スクリプトの解除 (セルラー用):
    6. /vendor/bin/init.class_main.sh (Line 40) の setprop ro.vendor.radio.noril yes を no に修正。
